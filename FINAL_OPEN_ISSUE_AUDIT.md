# Final Open-Issue Audit

Audit baseline: `main` at `92b6e92` (also `origin/main`) on 2026-08-21. The only pre-audit working-tree change was this report file. GitHub had 18 open issues and one open pull request, #43.

Verification performed during the audit:

- `pnpm test`, `pnpm typecheck`, `pnpm lint`, and `pnpm build` passed.
- `pnpm format:check` failed on five existing tracked files plus this newly created report before formatting.
- The offline CLI validator accepted all 100 entries in each valid acceptance dataset with zero rejections.
- A direct transport probe reproduced issue #5: a `ScrapeError` with code `cancelled` became a retryable `network_error` carrying `causeCode: "cancelled"`.
- The ignored local `output/` directory contains four old 20-request Instagram runs. It contains no TikTok run, continuous-session artifact, 5,000-request run, or acceptance evidence suitable for submission.

### 2. Must Fix

1. **Fix #5 before collecting any final runs.** Operator cancellation currently creates false retryable network failures in the primary JSONL deliverable and corrupts failure/success-rate evidence.
2. **Fix #27 before high-concurrency proxy acceptance.** The earned-capacity work increased the number of concurrent outcomes that can incorrectly spend and extend one proxy's failure budget.
3. **Fix #28 before treating proxy summaries as acceptance evidence.** Evicted failed proxies are currently represented as never-tested proxies, which makes the summary materially false.
4. **Make wait telemetry honest (#11).** The smallest acceptable change is to label/document it as aggregate job-time; do not present it as wall-clock duration.
5. **Resolve #9 through measurement, then complete #31.** Configure an actual HTTP egress ceiling during the live runs, tune concurrency/proxy capacity, and demonstrate 500 logical requests/minute for 10+ minutes with at least 95% success separately for TikTok and Instagram.
6. **Review and merge PR #43 before Instagram acceptance.** Current `main` does not include its unavailable-media and CSRF-bootstrap classification fixes. Those fixes directly affect success/error accuracy and retry/proxy behavior.
7. **Package the acceptance evidence.** Commit or otherwise include the final JSONL samples, run/session summaries, proxy-event evidence, and the required accuracy review. Ignored local files and prose referring to absent artifacts are not a deliverable.
8. **Resolve the TikTok view-accuracy conflict.** README states that large TikTok views can be rounded, while the take-home explicitly forbids rounded counts. The research-branch Apify fallback is also disallowed by the take-home's no-paid-scraping-API rule. Either find a compliant exact source or disclose this as an unmet blocker rather than presenting rounded values as acceptance-compliant.
9. **Resolve worker-count compliance.** The code has good ports and configurable in-process concurrency, but no configurable worker count or implemented horizontal execution. The take-home explicitly requires worker count to be configurable; architecture seams alone do not satisfy that wording.

Per-row proxy attribution (#29), connection-pool reuse (#16), richer stall episodes (#17), timestamp redesign (#15), and residential comparison controls (#40) should not be pulled into the finish-line scope unless acceptance evidence exposes a concrete need.

### 5. Potential Missing Requirements

- **No qualifying acceptance artifacts:** there are no committed 500-rpm, 10-minute, 5,000+-request summaries for both platforms, nor evidence that valid live URLs achieved ≥95% success. Issue #31 covers the general soak gap but does not explicitly cover both platform artifacts and the 95% bar.
- **No accuracy spot-check package:** the repository contains no screenshots or side-by-side verification for 10 randomly chosen posts per platform.
- **TikTok exact views are not satisfied:** README explicitly says large views may remain rounded. This conflicts with the required exact integer counts and has no open issue on `main`.
- **No implemented worker-count control:** the application is single-process. Configurable concurrency and architectural ports do not demonstrate horizontal scaling or configurable workers.
- **No observed account/session burn rate:** session rotation exists and is tested, but README §13 says the authenticated Instagram fallback still needs live validation. The required observed burn-rate note is absent.
- **Acceptance outputs are not packaged:** `data/examples/sample-output.jsonl` exists, but no representative final run summary accompanies it; local `output/` artifacts are ignored and incomplete.
- **Instagram correctness work is untracked as an issue:** PR #43 fixes unavailable-media and bootstrap classification but is still open and absent from the audited codebase.
- **Formatting verification fails:** five tracked baseline files fail `pnpm format:check`. This does not break runtime behavior, but it prevents a fully green final verification claim.
- **Documentation references unavailable evidence:** `docs/architecture-presentation.md` says its throughput/bandwidth figures come from committed `output/` artifacts, but those artifacts are ignored and absent from the repository history visible at this baseline.
